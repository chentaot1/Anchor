# Windows improvement log

## October 10, 2026

- Focus uses elapsed monotonic time instead of counting UI wake-ups. Late updates catch up immediately, pauses retain fractional seconds, and live duration adjustments retain elapsed time.
- Session history and rewards use actual elapsed focus time even when the timer is shortened or extended. Completion writes run independently of the timer effect so stopping that effect cannot cancel the save. Restorative breaks no longer activate focus-only blocking or scope checks; standing protection still applies.
- Individual task deletions and Clear Completed offer Undo, including after switching tabs. Restoration preserves notes, duration, difficulty, completion, timestamps, and ordering; it does not overwrite a conflicting record or replace a newly selected next action. Undo history lasts until dismissed or the app closes. New milestone text is cleared only after saving successfully.
- Running and paused focus sessions retain their original task attribution when the planner changes. Switching sessions credits eligible work on the previous task once, and completing an already completed focus task does not reopen it.
- Default duration changes apply after the current session. Explicitly changing the current focus length preserves elapsed time and updates its remaining time, including when paused.
- Space activates the focused control before falling back to the timer shortcut. Planner buttons identify their task, navigation exposes selection state, and micro-step checkboxes expose their checked state. Navigation scrolls when the window is too short to show all entries.
- A Windows tray icon reopens the minimized app. Focus and break completion notifications make finished background timers visible.
- Git update checks report unavailable standalone checks and failed branch comparisons accurately. A current source checkout no longer implies that an older running application image contains every fix.
- In-app source updates use fast-forward pulls, build the desktop classes before reporting success, and restart through Gradle after the previous instance exits. Update operations are serialized. Failed builds leave the current app running.
- Update command timeouts and cancellation terminate the process and its children. Output streams are drained together so verbose commands do not deadlock.
- The one-click updater checks pull/build failures, avoids restoring an unrelated stash, and launches updated source. Folder protection must be unlocked explicitly with the existing unlock tool before updating.

These changes improve source-based updates. Rebuild the Windows application image with `:desktopApp:createDistributable` to use them through `Launch-Anchor.bat`. No installer has been published for this development wave.

## October 11, 2026 — Backup and reset safety

- Restore validates the file and previews the sections and record counts before replacing data. Empty/unrelated JSON objects, malformed record sections, invalid values, ambiguous section aliases, and unsupported versions are rejected before deletion.
- A partial restore replaces only the sections supplied by the backup. Android assignment backups preserve Windows tasks and protection rules when those sections are absent. Explicit empty lists still clear the listed section.
- Restore, clearing the backlog, resetting focus history, and resetting tasks/progress require a recovery backup first. A failed backup write prevents deletion. Reset statements run in a transaction and roll back together if a later statement fails.
- Backup exports write and flush a temporary file before replacing the destination. Failed writes do not truncate the previous backup, and temporary files are cleaned up. Backup file and database work run off the UI thread.
- Restores and resets are unavailable during a running or paused focus session. Successful data replacement clears obsolete task-deletion undo history. Errors remain visible, and recovery file paths are reported after restoration.
- Seconds-based legacy focus-session aliases retain their durations. Importing session history without saved harbor totals refreshes those totals from the resulting history.
- Reset labels describe the records actually cleared and remove unsupported clinical claims. Backup actions and statistics wrap on narrower windows, and the restore preview scrolls when necessary.

- Recovery saves older work without moving the latest streak date backwards. Existing databases migrate the save-identity column without deleting old history.
